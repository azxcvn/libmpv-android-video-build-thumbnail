## 1. 为什么把解码器/解封装器/解析器改成全开

上游 `flavors/default.sh` 的做法是 `--disable-decoders` 关掉全部，再用手写白名单
逐个 `--enable-decoder=` 打开。**漏项的后果是静默失效**：构建成功、CI 全绿，
但那类格式**永远解不出来**，用户侧只看到「音轨/字幕能列出、选中后没反应、也没有任何提示」。

本项目实际踩到两次：

| 漏掉的组件 | 用户侧症状 |
|---|---|
| `pgssub` | 内嵌 PGS（蓝光位图）字幕轨能列出，**选中后完全不显示** |
| `truehd` | Dolby TrueHD（MLP FBA）音轨切过去后**完全无声** |

所以改成 `--enable-decoders` / `--enable-demuxers` / `--enable-parsers`，
从根上消掉「漏写」这一类问题。

**为什么这样做是可行的**：仓库自带的 `flavors/full.sh` 早就用这套开关，
而 `depinfo.sh` 里 `default` 与 `full` 的 `dep_ffmpeg` / `dep_mpv` **完全一致**
（都不含 `libx264` / `libvpx` / `libvorbis`）——即同一套依赖下，全开是上游自己验证过的组合。

**没有跟着改的**：协议、编码器、滤镜仍保持上游的精确白名单；`--disable-gpl` /
`--disable-nonfree` 等许可与平台开关也没动。

**代价实测**（`arm64-v8a`）：

| | 改动前 | 全开 | 增量 |
|---|---|---|---|
| `libmpv.so` 解压 | 20.75 MB | 24.68 MB | +3.93 MB |
| jar 压缩 | 8.71 MB | 10.9 MB | +2.19 MB |
| 解码器符号数 | 161 | 523 | +362 |

## 2. ⚠️ configure 组件名 ≠ codec 日志名

`--enable-decoder=<name>` 里的 `<name>` **不是**你在 mpv/ffmpeg 日志里看到的 codec 名。
写错会在 configure 阶段直接失败：

```
Unknown option "--enable-decoder=hdmv_pgs_subtitle".
```

写法取自源码里的符号 `ff_<组件名>_decoder`。本项目踩过的两个具体坑：

| codec 日志名 | configure 组件名 | 说明 |
|---|---|---|
| `hdmv_pgs_subtitle` | **`pgssub`** | 组件名来自符号 `ff_pgssub_decoder`，**不含** `hdmv_` 前缀 |
| `truehd` | **`truehd`** | 是独立组件名（`ff_truehd_decoder`），但**必须和 `mlp` 一起写** |

关于 `truehd` 这一段单独说明，因为它反直觉：

```c
#if CONFIG_MLP_DECODER
const FFCodec ff_mlp_decoder    = { .p.name = "mlp",    .p.id = AV_CODEC_ID_MLP,    ... };
#endif
#if CONFIG_TRUEHD_DECODER                    // ← 独立的开关，不会被 mlp 带出来
const FFCodec ff_truehd_decoder = { .p.name = "truehd", .p.id = AV_CODEC_ID_TRUEHD, ... };
#endif
```

两者在**同一个文件** `libavcodec/mlpdec.c` 里，但**各自有独立的 `#if CONFIG_*_DECODER`**，
是**两个不同的解码器**（codec id 都不同），**不是别名关系**。
实测：只写 `--enable-decoder=mlp` 时，产物里 `ff_truehd_decoder` 符号数为 **0**，TrueHD 依旧无声。

**结论：拿不准就把同类全写上，多写一个没有任何代价，漏写才有。**

## 3. 自检：如何判断某个能力是否真的编进去了

**只认符号名** `ff_<组件名>_decoder`。先解出 so：

```bash
unzip -o default-arm64-v8a.jar -d /tmp/k     # jar 就是 zip
SO=/tmp/k/lib/arm64-v8a/libmpv.so

# 三个关键能力（期望各 1，0 = 没编进去）
for s in ff_pgssub_decoder ff_mlp_decoder ff_truehd_decoder; do
  echo "$s = $(strings $SO | grep -c $s)"
done

# 已编入的解码器组件名总数（旧内核 161；全开后 523）
strings $SO | grep -o 'ff_[a-z0-9_]*_decoder' | sort -u | wc -l
```

**两个反例（都真实误导过我们）：**

1. **别用短名/长名字符串判断**。`--enable-small` 会把 codec 的 `long_name` 编掉，
   而短名会与其它字符串**互相包含**、被合并进一个大 blob，`grep -c` 的结果不可信。
2. **`strings libmpv.so | grep truehd` 是错的**：它会命中 `--enable-demuxer=truehd`
   带来的**解封装器**名字。解封装器在、解码器不在时，照样完全无声。

## 4. 其它踩坑

| 坑 | 结论 |
|---|---|
| 在 `../configure` 的**续行中间**插 `#` 注释 | bash 会把注释行当成参数接到上一行 → 语法错误。说明性注释一律写在 `../configure` **之前**，改完用 `bash -n` 校验 |
| `*_subtitle` 通配把需要外部库的解码器也打开 | `libaribcaption` / `libzvbi_teletext` 缺外部库会编译失败；`--disable-decoder=` 必须排在 `--enable-` **之后**（后者覆盖前者） |
| 用 `--enable-decoder=mlp` 期望带出 TrueHD | 见 §2，不带出，两者都要写 |
